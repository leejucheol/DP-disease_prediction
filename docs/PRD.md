# DP(Disease Prediction) 프로젝트 PRD

## 1. 개요

### 1.1. 프로젝트 목적

-   단백질 간 상호작용, 유전자 정보, 단백질 구조와 같은 다양한 생물학 데이터를 통합 분석하여 질병과 단백질 간의 연관성을 예측하는 시스템 개발
-   GCN(Graph Convolutional Network)을 활용하여 직접 연결뿐 아니라 다중 hop의 간접적 관계와 노드 속성(feature)을 동시에 학습, 이를 바탕으로 보다 정밀하고 신뢰도 높은 질병 예측 모델 구현

### 1.2. 배경 및 필요성

-   기존의 네트워크 기반 분석은 이웃 정보에 의존하여 복잡한 단백질 간 간접 관계를 반영하지 못하는 한계가 있음
-   단백질 서열, 기능, 구조 등 다양한 생물학적 속성을 통합하여 분석할 수 있는 AI 기반 접근법으로, 보다 일반화 가능한 예측 모델을 구축할 필요성이 대두됨

---

## 2. 기능 요구사항

### 2.1. 사용자 입력 처리

-   **입력 항목:**
    -   `Protein ID or Name` : UniProt ID, Protein ID 혹은 단백질 이름
    -   `Input Type` (선택): 미지의 단백질 또는 기존에 알려진 단백질 여부
    -   `Feature Option` (선택): 단백질의 기능, 구조, GO term 등의 포함 여부
-   **처리 내용:**
    -   입력받은 단백질 정보를 내부 단백질 식별자(Protein ID 또는 UniProt ID)로 변환
    -   변환된 ID를 기반으로 관련 생물학 데이터를 조회 및 전처리

### 2.2. 데이터 처리 및 모델 입력

-   **데이터 소스:**
    -   UniProt 메타데이터 (entryId, gene_x, geneSynonyms, isReferenceProteome, isReviewed, sequenceChecksum 등)
    -   질병 관련 데이터 (Disease ID, Disease Name, Gene ID, UniProt_ID, GO_Terms 등)
    -   단백질 간 상호작용 데이터 (protein1, protein2, combined_score)
-   **전처리:**
    -   다양한 데이터 컬럼을 통합하여 단백질의 feature 정보 생성
    -   누락된 데이터 혹은 노이즈에 대한 보정 및 처리

### 2.3. 모델 학습 및 예측

-   **모델 아키텍처:**
    -   GCN(Graph Convolutional Network)을 이용하여 단백질 노드와 그 속성을 학습
    -   k-layer GCN을 이용해 다중 hop 이웃의 정보를 자연스럽게 반영하여 간접적 관계 학습
-   **예측 내용:**
    -   입력 단백질에 대한 질병 예측: `related_diseases`와 score 제공
    -   유사 단백질 목록 예측: PPI 기반의 `related_proteins`와 유사도 score
    -   단백질 기능 요약: `functional_annotation` (GO term, 구조 정보 등)
    -   시각화용 그래프 데이터: 네트워크 구조(`nodes`, `edges`) 제공

### 2.4. 사용자 인터페이스

-   **입력 인터페이스:**
    -   단백질 ID 또는 이름 입력 및 관련 옵션 설정
-   **출력 인터페이스:**
    -   텍스트 기반 예측 결과 (질병 리스트, 유사 단백질, 기능 주석)
    -   시각화 도구를 통한 네트워크 그래프 제공

## 3. 비기능 요구사항

### 3.1. 성능

-   대용량의 생물학적 데이터를 효율적으로 처리할 수 있어야 함
-   실시간 예측 혹은 빠른 응답 시간을 목표로 설정

### 3.2. 확장성

-   향후 기능 확장(추가 데이터 컬럼, 향상된 시각화 등)에 대한 모듈화 및 확장성 고려
-   다양한 단백질 관련 데이터 소스를 추가로 통합할 수 있는 구조 필요

### 3.3. 신뢰성

-   데이터 무결성이 중요한 만큼, `sequenceChecksum` 등의 검증용 필드를 활용해 데이터 검증
-   노이즈 및 결손 데이터에 대한 강건한 처리 메커니즘 구축

### 3.4. 유지보수

-   코드와 모델의 모듈화 및 문서화를 통해 지속적인 유지보수가 가능하도록 설계

## 4. 프로젝트 구조 및 데이터 관리

### 4.1. 디렉토리 구조

-   `docs` : 프로젝트 문서와 참고 자료
-   `model-server` : API 서버 관련 코드, 데이터 파일(`train_data_small.csv`, `train_data.csv`) 포함
-   `models` : 학습된 모델 코드 및 체크포인트 관리
-   `ui` : 사용자 인터페이스 관련 코드

### 4.2. 데이터 관리

-   원본 데이터와 전처리된 데이터를 구분하여 관리
-   개인적/대용량 데이터(`train_data.csv`)는 별도 관리 (README에 명시된 주의사항 참고)

## 5. 개발 및 배포 계획

### 5.1. 개발 단계

1. **데이터 통합 및 전처리 모듈 구성**
    - 다양한 출처의 데이터를 통합할 수 있는 파이프라인 구축
2. **GCN 모델 학습 및 튜닝**
    - GCN 기반의 모델 설계, 학습, 검증 및 교차 검증 진행
3. **예측 결과 인터페이스 개발**
    - 입력 및 예측 결과 출력 인터페이스 구현 (텍스트 및 그래프 시각화)
4. **API 서버 구축**
    - FastAPI를 이용하여 backend API 서버 구축 및 통합 테스트 진행

### 5.2. 배포 전략

-   초기 베타 버전 배포 후 사용자 피드백 수집
-   성능 최적화 및 기능 추가를 위한 주기적 업데이트
-   Docker 등을 활용한 배포 및 스케일링 전략 고려
